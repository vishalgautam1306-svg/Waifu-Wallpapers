# Waifu Wallpapers — AI Lab

A **first integration test** of browser-based neural waifu2x processing, based on the open-source [nunif/unlimited:waifu2x](https://github.com/nagadomi/nunif/tree/master/waifu2x/unlimited_waifu2x) engine.

## What is implemented

- One wallpaper file selection and preview (no second upload).
- Original-image download.
- Genuine ONNX waifu2x inference (not Canvas interpolation), with model choices supporting 2× and direct 4×.
- Tile-by-tile browser processing, progress display, cancellation and output PNG download link.
- WebGPU/WebAssembly backend selection.
- No accounts or backend image uploads.

**Current status: source integration committed; real 2×/4× processing has NOT yet been verified on a deployed website or Android browser.** Model delivery is the outstanding deployment dependency.

## Deploying for testing

Connect this GitHub repository to Vercel as a **static/Other** project, root directory `/`, no build command.

The `vercel.json` rewrite forwards requests for `/models/*` to `https://unlimited.waifu2x.net/models/*`, so the public model files are delivered through your website origin. **This rewrite is experimental and unverified.** It depends on the upstream site maintaining these model URLs and permitting proxying, and is subject to Vercel's transfer, function, response-size and platform limits. Vercel may reject large ONNX model responses. Do not treat this as reliable production model hosting.

If model retrieval fails, obtain and self-host ONNX models from the [nunif releases](https://github.com/nagadomi/nunif/releases) in `models/swin_unet/art/` and `models/utils/`, preserving the exact names generated by `js/models.js`. Prefer an object-storage/CDN domain under your control for production with correct CORS. The official README documents `waifu2x_onnx_models_*.zip` model packages. Avoid putting large binary model files directly into Git.

If you deploy using GitHub Pages instead of Vercel, **the Vercel rewrite will not run**. You must supply the models separately.

## Device testing checklist

1. Load the HTTPS deployment on Android Chrome.
2. Select an anime wallpaper once. Use **Download original** to confirm source download.
3. Select **Swin UNet · Anime**, **AI 2×** and start. Leave the tab open.
4. Confirm the model loads and genuine progress increments. Check generated PNG pixels and visible detail.
5. Repeat with **AI 4×** and note peak memory use, completion time and download success.
6. Verify cancellation and error handling on low-memory devices.

### Important limitations

- A direct 4× model is used (it is **not** two sequential 2× passes).
- Initial model download can be large. AI execution happens on the device; model weights must still be delivered over the network.
- Mobile browsers may suspend processing if you leave the tab or lock the screen.
- Browser memory can prevent processing very large 4× images.
- Output download is via a browser blob URL; some in-app browsers may block this. Chrome is recommended.
- The existing upstream engine has limited error handling if models cannot be loaded. Test errors before a public launch.
- This test has no public gallery, upload moderation, storage, or account infrastructure.
